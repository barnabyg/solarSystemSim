# Procedural visual polish, zero asset dependencies

The premium look (ticket #11) — bloom and ACES tone mapping, atmosphere shells, Saturn's rings, the Sun's glow and corona, a dense starfield with a nebula backdrop, and soft shadows — is built entirely from code at runtime: shaders, canvas-generated textures, and DataTextures baked from catalog data. No image assets ship with the app. Chosen to keep the repo asset-free (same ethos as the procedural soundscape, ticket #12) and to keep every visual piece driven by the tested catalog data — ring bands and atmosphere colors live in the catalog and are asserted by data-integrity tests, so the look stays data-driven rather than hand-tuned in an asset file.

Post-processing runs through an EffectComposer (RenderPass → UnrealBloomPass → OutputPass) with the renderer on ACES filmic tone mapping and PCFSoft shadow maps; bloom renders at half-float resolution with a luminance threshold so only the bright bodies (the Sun, corona, brightest stars) glow. This is the ADR-0003 budget: the full pipeline stays within the high-end-desktop 60 fps target. The e2e suite cannot measure that target — the host runs software GL (SwiftShader) — so it guards a playable frame-rate floor instead (≥20 fps), and the composer's internal resolution adapts to the renderer: full screen on real GPUs, a reduced pixel ratio on software rasterizers, so the premium look is crisp where it is reviewed and the CI floor still passes. The ticket's "60 fps on target hardware" acceptance is verified by the user on their hardware, per ADR-0003.

**Considered Options**: image assets (textures for atmospheres/nebula) — rejected: adds sourcing and licensing overhead against the repo's zero-assets stance, and the visual data (band radii, gap positions, atmosphere colors) is real published data that belongs in the catalog where tests can pin it.
